# EKS Load Test Infrastructure (CloudFormation)

This directory defines AWS infrastructure for EKS-based load testing only.

## Directory Layout

- atlas-platform-eks-stack.yaml: shared platform resources (ECR + CloudWatch log group).
- env-stack.eks.yaml: per-environment EKS stack with larger node sizing.

## What Gets Provisioned

### atlas-platform-eks-stack.yaml (shared)

- ECR repository for the load runner image.
- CloudWatch log group for EKS load runs.

### env-stack.eks.yaml (per environment)

- Uses an existing EKS cluster provided at deploy time.
- S3 buckets for artifacts/results and access logs (names are auto-generated by CloudFormation to avoid global name collisions).
- IRSA role for the Kubernetes service account (`atlas-load/atlas-load-runner`).

## Required Parameters (env stacks)

- `EnvironmentName`
- `ExistingClusterName`
- `OidcProviderArn`
- `OidcIssuerHostPath` (without `https://`)

## Outputs

### platform outputs

- `EcrRepositoryUri`
- `LogGroupName`

### env outputs

- `ClusterName`
- `S3BucketName`
- `IrsaRoleArn`

## Deployment Order

1. Deploy `atlas-platform-eks-stack.yaml`.
2. Deploy `env-stack.eks.yaml` per environment.
3. Deploy/run the Kubernetes Job (Helm/manifests) using the output values.

## Required GitHub Repository Variables (for train.dispatch)

The workflow requires these repository variables to exist:

- `EKS_CLUSTER_NAME`
- `EKS_OIDC_PROVIDER_ARN`
- `EKS_OIDC_ISSUER_HOSTPATH` (without `https://`)

You can set them in GitHub UI:

- Settings -> Secrets and variables -> Actions -> Variables

Or with GitHub CLI:

```bash
gh variable set EKS_CLUSTER_NAME --body "eks-app-perf02"
gh variable set EKS_OIDC_PROVIDER_ARN --body "arn:aws:iam::<account-id>:oidc-provider/<oidc-hostpath>"
gh variable set EKS_OIDC_ISSUER_HOSTPATH --body "oidc.eks.<region>.amazonaws.com/id/<id>"
```

Quick lookup commands (AWS CLI):

```bash
aws eks describe-cluster --name <existing-cluster-name> --query 'cluster.name' --output text
aws eks describe-cluster --name <existing-cluster-name> --query 'cluster.identity.oidc.issuer' --output text
```

## Notes

- The load-test S3 bucket is retained on stack delete (`DeletionPolicy: Retain`).
- `PlatformEks-*` exports are used by workflows.
